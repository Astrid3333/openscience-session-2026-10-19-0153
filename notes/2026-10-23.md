# 2026-10-23 — Ciclo Cadabra2 (CIERRE)

## Cadabra2 2.6.0 — integración completa

- Autenticidad verificada (Author Kasper Peeters, cadabra.science,
  github kpeeters/cadabra2, DOIs JOSS/Zenodo, wheel manylinux cp312
  2.2MB con `.so` C++). Instalado en el venv (sympy 1.14.0, mpmath,
  matplotlib, ipykernel ya presentes). Sin CLI `cdb` en `.venv/bin`,
  sin `__version__` (→ `importlib.metadata.version("cadabra2")` =
  2.6.0), `import cadabra2` lazy 0.031s → subprocess-per-call barato.
  Manual `.cnb` NO incluido en la wheel (`help()` falla con "Failed to
  collect help information").
- Smokes (≈10 batteries): API completa mapeada. Hallazgos clave:
  - Propiedades (AntiSymmetric, Indices, Metric, SortOrder,
    AntiCommuting…) toman `Ex` (no str); las list-properties SOLO
    aceptan Ex con comas (`Ex('m, n, k')`); `Ex('m')` → RuntimeError
    "A list property cannot be assigned to a single object".
  - `canonicalise` NO cancela términos idénticos (sí reordena índices
    y aplica antisimetría); `collect_terms` SÍ cancela → 0 (pipeline
    canonicalise→collect_terms, mutan in place y retornan el Ex).
  - Fermiones: `canonicalise` NO reordena factores — el algoritmo es
    `sort_product`: SortOrder + AntiCommuting → sort_product →
    collect_terms → `ψ_1 ψ_2 + ψ_2 ψ_1` = 0.
  - `evaluate(Ex('1 + 1'))` → 2; el Ex crudo se queda `1 + 1`
    (numerales NO autoevalúan).
  - `expand` no-op en potencias `(x+y)**2`; `distribute` sí
    distribuye productos `x*(y+z)` → `x y + x z`; `simplify` cancela
    polinomios → 0.
  - `substitute` 2-arg (`Ex('pat = val')`): NO desciende a la base
    dentro de una potencia (`x^2 + y` con `x = a+b` queda igual);
    patrón completo `x^2 = a` sí funciona.
  - Puente sympy: usar `SympyBridge(ex).to_sympy()` (`sympy` global es
    un enum, no callable). Bug: `x^2` → símbolo `x(UP2)` (^ parseado
    como índice para el bridge); escribir `x**2`. `map_sympy` devuelve
    artefacto (`\sum(x^{2})()`) — no usar.
  - `Ex()` NUNCA lanza ante input malformado: trunca en silencio
    (`')'` → `''`, `'x +'` → `'x'`, `\partial_x{f` → árbol completo).
  - Kronecker δ NO contrae: `\delta_{m n} A^m` tras
    canonicalise+reduce_delta → `δ^{m}_{n} A_{m}` (probado con/sin
    Indices declarados, formas `\delta` y `KroneckerDelta(m,n)`,
    eliminate_kronecker/reduce_delta/canonicalise); `eliminate_metric`
    SÍ funciona (`g_{m n} g^{n k}` → `g_{m}^{k}`).
- `cadabra2_math_tool.py` (patrón lispium): `mode=compute` con ops
  estructuradas (canonicalise, collect_terms, substitute, elim
  metric, sort_product, distribute, evaluate, simplify, to_sympy),
  `eval` de código python cadabra libre (prelude
  `from cadabra2 import *`), `guia` con todos los quirks; runner =
  subprocess fresh por llamada con `.venv/bin/python` del repo (las
  propiedades son estado global del proceso — el aislamiento evita
  sangrado). Errores: subprocess raise → ok=False + stderr; handler
  raise → texto isError "ValueError: …".
- **18 validate checks** (todos pins de smoke): basic eval, antisym
  canonicalise, commutator ∂x f∂y f−∂y f∂x f → 0 por pipeline, metric
  elimination, substitute escalar/patrón-completo/base-pin,
  grassmann → 0, evaluate-vs-raw, simplify → 0, distribute, expand
  no-op pin, bridge limpio, bridge `^` bug pin, Ex silencioso pin,
  list-property conas pin, delta no-contrae pin, fence python.
- Verificación: validate directo 18/18 (0.1s/check); suite
  **370 registradas / 352 evaluadas / 352 PASSED / 0 FAILED /
  0 ERROR / 18 SKIPPED** (177.8s); health por wire `healthy`
  (331.6s, 352/0/18); wire smoke compute 8/8 OK; ejemplo
  `examples/cadabra2_tensor_canonicalisation.py` **12/12 PASS**
  (cadena antisym+metric+grassmann+simplify+substitute+bridge+fences).
- Ruff limpio en tool + ejemplo; SKILL.md actualizado (370+, list_full
  367, bullet Cadabra2 18 checks) y `regenerate_skill_content.py`
  (check_sync True, 15419 bytes). Commit + push (ver git log).

### Lecciones (Cadabra2)

- Propiedades simbólicas vivas en el proceso (Indices/Metric/…) hacen
  del subprocess-per-call una NECESIDAD de corrección, no solo de
  rendimiento: cada llamada debe declarar su estado o el validate
  fallaría por sangrado cruzado entre herramientas.
- Antes de publicar una limitación ("δ no contrae"), agotar el
  espacio sintáctico: formas LaTeX vs función, con/sin índices
  declarados, y TODOS los algoritmos del directorio. Si persiste,
  fijarla como check pin verde en validate + guía + skill (regla ya
  establecida en Lispium, aplicada aquí).
- Un CAS cuyo parser "nunca lanza" (Ex trunca en silencio) necesita
  cercas de error en el REVESTIMIENTO, no en el parser: probar las
  dos vías (raise de python en subprocess → ok=False; raise del
  handler → texto isError) y dejar ambas como checks.

## Router unificado de CAS — `cas_router_math_tool` (CIERRE)

- Decisión del usuario: integrar el router (no cerrar el backlog).
- `cas_router_math_tool.py`: despacho a los 4 CAS en proceso vía
  `tool_registry.get_handler` (sin wire ni recursión; imports
  defensivos de los 4 motores para garantizar el registro). `mode=
  compute, operation=eval` recibe `query` en la sintaxis del motor
  destino — NO traduce sintaxis. Orden de ruteo: `engine` explícito >
  hint `field` (tensor/fisica→cadabra2, numero/prime→sagebrush,
  laplace/calculo→maxima, lisp→lispium) > sniff del contenido (LaTeX
  `_{{`/`\psi`→cadabra2, `euler_phi`/`is_prime`→sagebrush, `(^ `/`(factor`…→lispium, `%e`/`diff(`→maxima) > default maxima.
  Con `fallback=true` (default) encadena los otros 3 motores y
  reporta `engine_used` + `attempts[]` (quién falló y por qué).
  `operation=guia` devuelve la tabla de ruteo + nota de cross-check.
- Adaptaciones por motor descubiertas en el smoke (ahí está el
  descubrimiento, no en el diseño inicial):
  - cadabra2 no evalúa expresiones crudas (`A_{m n}` → SyntaxError):
    el router la envuelve en `print(str(evaluate(Ex(<json>))))`.
  - sagebrush: op `sage` (no `python`) para matemática — y el nombre
    correcto es `euler_phi` (Sage), NO `eulerphi` (Maxima); el sniff
    separa ambos nombres hacia su motor.
  - lispium `expt` es función desconocida silenciosa (exit 0,
    devuelve el form sin evaluar) — potencia real: `(^ 2 10)` → 1024;
    el check de lisp usa `(^ 2 10)`.
  - lispium acepta símbolos LaTeX desconocidos con exit 0 (echos),
    por eso el fallback "funciona" con queries rotas: el log
    `attempts[]` es lo que permite distinguir éxito real de eco.
- **10 validate checks**: route explicit/latex/maxima/sagebrush/lisp,
  field hint, fallback chain (maxima→sagebrush→lispium), all-fail
  report (4 intentos fallidos), normalización de result, fence de
  engine desconocido (ValueError). Directo: **10/10**.
- Registro en `server.py` tras cadabra2. Suite
  **371 registradas / 353 evaluadas / 353 PASSED / 0 FAILED /
  0 ERROR / 18 SKIPPED** (169.3s); health `healthy` 353/0/18;
  ejemplo `examples/cas_router_dispatch.py` **9/9 PASS**.
- SKILL.md: 371+, list_full 368, bullet del router (regla sin
  backslash — el embebido r-string de skill_content lo rechaza;
  reescribir como texto plano), health 371/353/353; skill_content
  regenerado (check_sync True, 16359 bytes). Ruff limpio en tool +
  ejemplo (server.py: issues pre-existentes, no tocados).

### Lecciones (router)

- Un router que "no traduce sintaxis" sigue necesitando un
  adaptador mínimo por motor (envolver Ex en evaluate, elegir op
  sage vs python): el descubrimiento de esos 3 adaptations sólo fue
  posible corriendo el smoke ANTES de fijar los checks — diseñar el
  smoke de despacho primero, no después.
- Respuestas con "eco silencioso" (lispium devuelve el form sin
  evaluar con exit 0) hacen que el fallback parezca exitoso
  engañosamente: el `attempts[]` con ok+error por motor es parte
  obligatoria de la respuesta, no un extra.
- Regla nueva de skill: el markdown embebido en skill_content es
  r-string — nada de backslash en SKILL.md (escribir 'cusps' o
  comillas simples a mano).


## Ciclo 6 — Cross-check multi-motor (decisión: "más cross-checks")

**Goal**: batería de problemas matemáticos resueltos en los 4 CAS
(sagebrush, maxima, lispium, cadabra2) y comparados contra oráculo
sympy en vivo.

- **Sondas de adaptación** (patrón router: descubrir antes de fijar
  checks):
  - sagebrush es **shim sin paquete `sage` real**
    (`ModuleNotFoundError: No module named 'sage'`): `var()` crea
    símbolos pero **no inyecta en globals** → workaround fijado
    `x, y = var('x y')` (asignar el retorno). Con eso funcionan
    `solve`, `limit` → `e`, `symbolic_sum(1/k^2, k, 1, oo)` →
    `pi^2/6`, `matrix(...).det()` → −2, `factorial`, `euler_phi`.
    `sum(...)` con tupla falla (`'Expression' object is not
    iterable`): el shim expone `symbolic_sum(expr, var, a, b)`.
  - maxima: nombre correcto de determinante es `determinant(...)`
    (no `det`), devuelve −2 sin `load("eigen")`. `factorial(20)`
    y `2^61-1` exactos. `primep` → `true`.
  - lispium: parser propio necesario (s-expr → sympy); `(^ 2 61)` y
    `(factorial 20)` degradan a **float** (pin); `simplify` devuelve
    la forma re-impresa sin reducir (pin); regla del producto, gcd y
    `(^ 2 10)` correctos.
  - cadabra2: `D` no está en el namespace de eval; identidad
    polinómica y entero grande exactos vía
    `print(str(evaluate(Ex(...))))` con `**`.
- **Ejemplo** `examples/multi_cas_crosscheck.py` (Wire stdio
  self-contained, 13 problemas × motores + 6 pins de quirks = **34
  checks**): derivada de producto (3 motores), integral definida,
  factor x⁴−1, sistema 2×2, gcd (3 motores), limit→e, primalidad
  2^61−1, entero grande exacto (3 motores), identidad (x+1)²−x²−2x−1
  (3 motores), determinante, totient, factorial, Basel; pins: maxima
  noun-form con ok=True (eulerphi, sum), lispium float (big-int,
  factorial) y eco de simplify, sage `var()` sin inyección.
- **Resultado**: ruff limpio; ejemplo **34/34 PASS**.
- Dos bugs de pins cazados en la primera corrida (33/34):
  1. pin sage usaba `'y'` pero la sesión persistente del server ya
     tenía `y` inyectado por `x, y = var(...)` previo → nombres
     frescos `qq ww` + chequeo semántico (`r.strip() == "False"`,
     no `"y" not in split()` que pasaba siempre);
  2. pin lispium buscaba "simplify" en la última línea, que devuelve
     la forma re-impresa sin esa palabra → condición real:
     `last != "0" and "(^" in last`.

### Lecciones (cross-check)

- La sesión sagebrush dentro de server.py es **persistente entre
  llamadas**: cualquier check que observe estado global (inyección de
  `var`) depende del orden → usar nombres jamás asignados antes, o
  aislar.
- Un check de pin debe expresar la semántica del quirk
  (`== "False"`), no un sub-string accidental del output que pasa
  siempre: el primer pin de sage "pasaba" aunque el quirk no
  existiera.
- Verificar compatibilidad de motores por sondas ANTES de escribir
  la batería: 4 de 13 problemas habrían fallado por dialectos
  (`%e`, `==` vs `=`, `euler_phi`, `symbolic_sum`) descubiertos
  solo al sondear.
